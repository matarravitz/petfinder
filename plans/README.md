## Dependency notes

- No plan in this batch has a hard dependency on another — all 9 touch
  disjoint code paths or, where they share a file (`postsApi.js` in Plans
  003/004/006/008; `MyPostsDashboard.jsx` in Plans 006/007), disjoint
  functions or line ranges within it. They can be executed in any order or
  in parallel worktrees.
- Recommended sequencing anyway: **001 first** (CI is the safety net every
  other plan benefits from, per the audit's tiebreaker rule — land it before
  anything risky). **003 before 002** if both are executed together, purely
  to claim migration numbers in order (both add a new
  `supabase/migrations/000X_*.sql` file; check `ls supabase/migrations/`
  immediately before creating either, and let whichever runs second pick
  the next free number).
- Plan 003 modifies `deletePost` in `postsApi.js` (adds photo cleanup). If
  Plan 006 (which adds a new `deletePosts` plural function) is executed
  after 003 has landed, Plan 006's Step 1 explicitly branches on which
  version of `deletePost` it finds — no action needed beyond following that
  plan's own instructions.
- Plan 007 explicitly scopes itself to skip the sweep effect in
  `MyPostsDashboard.jsx` (lines 21-46) so it never conflicts with Plan 006,
  regardless of execution order.
